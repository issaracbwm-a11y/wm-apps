# ข้อมูลกลางทะเบียนเครื่องชั่งรถยนต์

ผู้เข้าชมยังเปิดหน้าสาธารณะได้จากลิงก์เดิม ผู้ดูแลส่งลิงก์เปิดสิทธิ์ที่ใช้ได้หนึ่งครั้งให้แต่ละเบราว์เซอร์ อุปกรณ์ที่เปิดสิทธิ์แล้วอ่านและเขียนทะเบียนกลางโดยไม่ต้องมีบัญชีแยก ข้อมูลใน IndexedDB เดิมจะอยู่ในโหมดบนอุปกรณ์ จึงสามารถส่งออกไปย้ายเข้าได้โดยตั้งใจ

## ตั้งค่าฐานกลาง

1. ใช้โปรเจกต์ Supabase สำหรับงานนี้ เปิด Data API สำหรับ schema `public` และรัน migration ใน `supabase/migrations/` โดยคง `wm_truck_private` ไว้นอก exposed schemas
2. ตั้ง `js/sync-config.js` ด้วย Project URL, publishable key และ origin ที่จะให้เจ้าหน้าที่ใช้ เช่น `https://ทะเบียน.example.go.th` โดยใช้ชื่อโฮสต์จริงในรูปแบบที่เบราว์เซอร์แสดง ห้ามใส่ secret key, service-role key, ลิงก์เปิดสิทธิ์ หรือข้อมูลทะเบียนใน Git
3. สำหรับใช้งานจริง ให้ใช้ origin HTTPS แยกสำหรับเว็บนี้เพื่อให้สิทธิ์ที่เบราว์เซอร์จำไว้ถูกแยกจากสคริปต์เว็บอื่น โฟลเดอร์ในโดเมนเดียวกันใช้พื้นที่เก็บข้อมูลของเบราว์เซอร์ร่วมกัน
4. ผู้ดูแลฐานข้อมูลสร้างลิงก์เปิดสิทธิ์ครั้งแรกจาก SQL Editor โดยใช้คำสั่งด้านล่าง แล้วนำค่า `invite_code` ไปต่อหลัง `/#/sync?invite=` ใน URL ของเว็บ ส่งผ่านช่องทางภายในเท่านั้น

```sql
with invitation as (
  select replace(gen_random_uuid()::text || gen_random_uuid()::text, '-', '') as code
), inserted as (
  insert into wm_truck_private.invites (digest, label, is_admin)
  select sha256(convert_to(code, 'UTF8')), 'ผู้ดูแลทะเบียน', true
  from invitation
  returning expires_at
)
select invitation.code as invite_code, inserted.expires_at from invitation cross join inserted;
```

หลังเปิดสิทธิ์ผู้ดูแล ใช้เมนู **ข้อมูลกลางของทีม** สร้างลิงก์สำหรับเจ้าหน้าที่และถอนสิทธิ์อุปกรณ์ของเจ้าหน้าที่ได้ หากต้องถอนสิทธิ์อุปกรณ์ผู้ดูแล ให้ผู้ดูแลฐานข้อมูลอัปเดต `revoked_at` ให้กับแถวอุปกรณ์ที่ยืนยันแล้ว

## เผยแพร่หน้าเจ้าหน้าที่บน Cloudflare Pages

ถ้าศูนย์ยังไม่มีโดเมน ใช้ชื่อโฮสต์ HTTPS ที่ Cloudflare Pages ให้กับโปรเจกต์ เช่น `https://<ชื่อโปรเจกต์>.pages.dev` โดยใช้ URL ที่ Cloudflare แสดงจริง

| การตั้งค่า Pages | ค่า |
|---|---|
| Repository | `issaracbwm-a11y/wm-apps` |
| Production branch สำหรับทดสอบ | `feat/truck-scales-supabase-sync` |
| Root directory | `truck-scales` |
| Build command | `node build-staff.mjs` |
| Build output directory | `dist-staff` |
| WM_SUPABASE_URL | HTTPS Project URL ของ `wm-smart-inspection` |
| WM_SUPABASE_PUBLISHABLE_KEY | Publishable key ของโปรเจกต์ |
| WM_STAFF_ORIGIN | URL `https://…pages.dev` ของหน้าเจ้าหน้าที่ โดยไม่มีเครื่องหมายทับท้าย |

การ build สำหรับหน้าเจ้าหน้าที่จะตั้งค่า Supabase เฉพาะไฟล์ผลลัพธ์ ส่วน GitHub Pages เดิมใช้ค่าเริ่มต้นสำหรับหน้าสาธารณะ ผลลัพธ์ build มีเฉพาะไฟล์หน้าเว็บและไลบรารีที่ใช้ในเบราว์เซอร์

## ย้ายข้อมูลและตรวจรับ

- รวมไฟล์สำรองเดิมในโหมดบนอุปกรณ์ ตรวจรายการซ้ำและยอดตามประเภท แล้วให้ผู้ดูแลนำไฟล์รวมเข้าฐานกลางครั้งแรก หรือเปิด Excel เมื่อยังไม่มีผลตรวจเดิม ฐานกลางที่มีข้อมูลแล้วใช้วิธีนำเข้า Excel รอบใหม่พร้อมตรวจค่าที่ขัดกัน
- การนำไฟล์สำรองเข้าครั้งแรกและการบันทึกผลตรวจกับไฟล์แนบใช้ธุรกรรมเดียว รองรับไม่เกิน 2,500 รายการและ 32 MiB ของ JSON ต่อคำขอ ข้อมูลแนบอยู่ในฐานข้อมูลเพื่อให้ทำรายการพร้อมผลตรวจได้ ชุดที่เกินขนาดต้องวางแผนแบ่งนำเข้าก่อนใช้งานจริง
- ทดสอบสองอุปกรณ์โดยเพิ่มสถานที่ แก้พิกัด บันทึกผลตรวจ และโหลดข้อมูลล่าสุดบนอีกเครื่อง ทดสอบกรณีแก้ข้อมูลเดียวกันพร้อมกันและกรณีถอนสิทธิ์
- ในโหมดฐานกลาง การบันทึกต้องได้รับการยืนยันจากเซิร์ฟเวอร์ เมื่อไม่มีอินเทอร์เน็ตให้ลองใหม่เมื่อเชื่อมต่อได้ การล้างหรือแทนที่ทั้งชุดและการลบเครื่องจากทะเบียนกลางถูกปิดไว้ในรุ่นนี้

ฟังก์ชันภายในตรวจสิทธิ์อุปกรณ์ทุกคำขอและฐานข้อมูลเก็บเฉพาะแฮชของรหัสเปิดสิทธิ์และรหัสอุปกรณ์ ตรวจสิทธิ์จากเบราว์เซอร์สาธารณะด้วยว่าเปิดได้เฉพาะยอดสรุป และทดสอบผ่าน Data API จริงก่อนนำข้อมูลของศูนย์ขึ้นระบบ
